# Ranex visual identity

`PROVISIONAL` — the palette is adopted and generated; the wider redesign it
serves has no accepted ADR yet.

## What was wrong

`packages/tui/src/theme/assets/ranex.json` was **opencode's stock palette with
the name changed**. Its `$schema` pointed at `https://opencode.ai/theme.json`
and its primary was opencode's orange `#fab283`. It is also the *default* theme
(`context/theme.tsx` falls back to `"ranex"` in five places), so this was what
every user saw.

Underneath, 38 hex values were hand-maintained per file under positional names —
`darkStep1` … `darkStep12`, `lightStep9`. A name like `darkStep9` tells you
nothing about when to use it, which is how light and dark drift apart and how a
palette becomes unowned.

## What it is now

Generated by `packages/tui/script/generate-ranex-theme.ts` from **19 semantic
base tokens per mode**, taken from the approved ranex.dev palette
(`ranex-web/index.html`). Do not edit the JSON; edit `BASE` in the script and
re-run:

```sh
bun run packages/tui/script/generate-ranex-theme.ts
```

### Base tokens

| Token | Light | Dark | Means |
|---|---|---|---|
| `ground` | `#F4F6F7` | `#0E151D` | the page |
| `surface` | `#FFFFFF` | `#16202A` | a raised element |
| `surface2` | `#EDF1F3` | `#121B24` | a panel |
| `ink` / `inkSoft` | `#1B2733` / `#52616E` | `#E9EDF1` / `#9DACB9` | text, muted text |
| `line` / `lineStrong` | `#D9E0E4` / `#B9C4CC` | `#26333F` / `#3A4B59` | borders |
| `accent` / `accentStrong` | `#2B5C8A` / `#234C73` | `#7FB0DC` / `#9CC3E8` | brand blue, structural |
| `pass` / `passBg` | `#1E7A45` / `#E7F2EB` | `#4FB27E` / `#14281E` | **`Verdict.PASS`** |
| `fail` / `failBg` | `#B23A32` / `#F7E9E7` | `#E07B6F` / `#33201D` | **`Verdict.FAIL`** |
| `warn` / `warnBg` | `#8A6114` / `#FAF0DC` | `#D9A441` / `#2A2114` | attention, *not* a verdict |
| `info` / `infoBg` | `#1F6E73` / `#E3F1F2` | `#6FC3C8` / `#13272A` | informational |
| `highlight` | `#6A4FB0` | `#A99BE0` | emphasis, keywords |

`pass` and `fail` are brand tokens, not decoration — they are the two values of
`Verdict`. That the marketing palette already carried them is why it was worth
adopting wholesale rather than inventing a second identity for the terminal.

`warn` and `info` are the only derived additions. The site never needed them: a
marketing page never has to say *attention, but this is not a verdict.*

### One mapping, both modes

The 50 `ThemeColor` keys map to base tokens through a single table that does not
branch on mode, so a key cannot mean one thing in light and another in dark —
the exact drift the hand-maintained file allowed.

## The contrast gate

Adapted from Textualize/textual `src/textual/design.py`
@ `1d99508b928a771b51e1a527319c6b87dcff9e05`, which declares a few semantic
colours and derives the rest.

**The gate is the part Textual does not give you.** `ColorSystem` shades by
luminosity arithmetic and never checks a generated shade against the surface it
lands on; contrast is handled elsewhere in Textual, and a naive adopter ships an
unreadable palette. So the check is a build gate here: the generator computes
WCAG 2.1 contrast for every foreground/background pair it intends to emit and
**writes nothing** if any pair is under its floor.

| Pair | Floor | Why |
|---|---|---|
| `ink` on any surface | 4.5:1 | WCAG AA body text |
| `pass`/`fail`/`warn`/`info`/`accent`/`highlight` on any surface | 4.5:1 | a verdict you cannot read is a failed verdict |
| status colour on its own tint (`pass` on `passBg`) | 4.5:1 | diff rows and callouts |
| `inkSoft` on any surface | 3.0:1 | AA for large/secondary text |
| `line` / `lineStrong` on `ground` | 1.2:1 / 1.5:1 | a border is seen, not read |

**60 checks, all passing.** Tightest margins are light-mode `pass on surface2`
at 4.71:1 and `pass on passBg` at 4.66:1 — both clear AA, and both are the pairs
to re-measure first if `BASE` ever changes.

## Verified

- `bun test` in `packages/tui` — 191 pass, 1 skip, 0 fail, 8 snapshots
- `bun run typecheck` — clean
- Generated JSON: 50 theme keys (identical key set to the stock themes), 38
  defs, no dangling refs

## Not done

- **Degraded 16-colour / `NO_COLOR` path.** `lipgloss-color.go`'s `NoColor` —
  foreground falls back to the terminal default, background is not drawn at all
  — is the model, and `LightDark`'s caveat applies: terminal background
  detection is unreliable and must never override a declared default. Not built;
  belongs to the ADR-018 slice.
- **The other 32 themes** still carry opencode's structure. They are not the
  default and are out of scope until the redesign lands.
- Glyph set (`✔`/`✖` with ASCII fallback, per `cliui-icons.ts`) is specified in
  `design-references.md` but not implemented.
