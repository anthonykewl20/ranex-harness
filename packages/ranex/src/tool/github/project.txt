Manage GitHub Projects (v2) with a flat top-level `action` contract. Do not use an `operation` field. Top-level `owner` is always required and is the organization or user login that owns the project.

- `list`: `{ "action": "list", "owner": "acme" }`
- `get`: `{ "action": "get", "owner": "acme", "number": 7 }`
- `create`: `{ "action": "create", "owner": "acme", "title": "Roadmap" }`
- `add_item`: `{ "action": "add_item", "owner": "acme", "number": 7, "content": { "owner": "acme", "repo": "widgets", "number": 42 } }`
- `set_field`: `{ "action": "set_field", "owner": "acme", "number": 7, "field_name": "Status", "value": "In progress", "content": { "owner": "acme", "repo": "widgets", "number": 42 } }`

Top-level `number` is the project number. `content.number` is the issue number. These identifiers accept positive integers or decimal digit strings.

`field_name` is case-sensitive. Supported field types are `single_select`, `text`, `number`, and `date`. For `single_select`, `value` must exactly match an existing option name. For `text`, it is used verbatim. For `number`, it must be numeric. For `date`, it must be a parseable date value.

Requires GitHub authentication. Every operation requires approval using `projects:read:owner` or `projects:write:owner` permission patterns.
