Manage GitHub issues with a flat top-level `action` contract. Do not use an `operation` field.

- `list`: `{ "action": "list", "state": "open", "labels": ["bug"], "milestone": 3 }`
- `get`: `{ "action": "get", "number": 42 }`
- `create`: `{ "action": "create", "title": "Bug report", "body": "Steps to reproduce", "labels": ["bug"], "assignees": ["octocat"], "milestone": 3 }`
- `update`: `{ "action": "update", "number": 42, "title": "Updated title", "body": "Updated details", "state": "open" }`
- `close`: `{ "action": "close", "number": 42 }`
- `comment`: `{ "action": "comment", "number": 42, "body": "Fixed" }`

`list` defaults `state` to "open"; valid states are "open", "closed", and "all". Update state may be "open" or "closed". Issue and milestone identifiers accept positive integers or decimal digit strings.

`owner` and `repo` are optional and default to the current git origin. Supply both together to target another repository; supplying only one is invalid. For example: `{ "action": "get", "owner": "acme", "repo": "widgets", "number": 42 }`.

Requires GitHub authentication. Every operation requires approval using `issues:read:owner/repo` or `issues:write:owner/repo` permission patterns.
